# Инструкции для Claude Code

Книга «Дерево метаданных 1С: как читать и понимать». **Книга завершена** —
все 10 модулей написаны, отрецензированы и отредактированы. Текущая работа:
поддержка, сверка фактуры, подготовка печатного издания.

Перед любым действием прочитай контекст:

- **`spec/constitution.md`** — принципы книги: что она ЕСТЬ и что НЕ ЕСТЬ,
  каноничные метафоры, терминология регистров, запреты. Если предложение выходит
  за рамки конституции — откажись от него, даже если оно кажется полезным.
- **`spec/specification.md`** — для кого книга, что читатель знает на входе,
  метрики успеха, ограничения.
- **`spec/decisions.md`** — лог принятых решений. Перед предложением нового
  решения проверь, не принималось ли оно уже.
- **`docs/style-guide.md`** — канон стиля серии.
- **`docs/plan.md`** — полный план книги: концепция, все модули, все параграфы.
- **`metadata.yaml`** — версия, форматы, статусы.

## Структура репозитория

```
chapters/
  NN_название_модуля/
    NN-MM_название_параграфа.md   ← frontmatter обязателен

assets/img/     ← обложка и иллюстрации

docs/           ← план книги и гайды для автора
reviews/        ← отчёты панели ревью (не идут в сборку)
```

Модули: `00_vvedenie`, `01_spravochniki`, `02_dokumenty`,
`03_registry-svedeniy`, `04_registry-nakopleniya`, `05_otchety`, `06_svyazi`,
`07_drugie-obekty`, `08_kak-chitat-bolshoe-derevo`, `09_zavershenie`.

Параграфы: `01-01_spravochnik-kak-spisok.md`. Нумерация непрерывная внутри
модуля, с ведущим нулём. Последний файл модуля — `NN-MM_itog.md`.


## Структура параграфа (строго соблюдать)

1. **Открытие** — связь с предыдущим + ориентир: где смотреть в Конфигураторе.
2. **Содержательные разделы** (4–7) с выносками `>`, примерами, ASCII-схемами.
3. **Главное** — один плотный абзац.
4. **Контрольные вопросы** — 5–7.
5. **Упражнения** — минимум три вида:
   - «Найди в Конфигураторе» — наблюдение;
   - «Посмотри и ответь» — интерпретация, **обязательно** содержит вопрос
     «почему здесь так?» или «что сломается, если изменить?»;
   - «Спроектируй» — самостоятельное создание структуры.
6. **Ответы и указания**.
7. **Мостик** — переход к следующему параграфу.

## Сквозной пример: состояние дерева «Канцтоваров»

К концу книги:

```
Конфигурация «Канцтовары»
├── Справочники: Товары, Контрагенты, Склады
├── Документы
│   ├── ПоступлениеТоваров      → ОстаткиТоваров (Приход)
│   └── ПриказОбИзмененииЦен    → ЦеныТоваров
├── Регистры сведений:   ЦеныТоваров      (Товар | Цена)
├── Регистры накопления: ОстаткиТоваров   (Товар, Склад | Количество)
└── Отчёты: ОстаткиТоваровНаСкладе (СКД → ОстаткиТоваров.Остатки)
```

Дерево растёт по модулям: 1 — справочники, 2 — документы, 3 — регистр сведений,
4 — регистр накопления, 5 — отчёт. Модули 6–9 объясняют и закрепляют, дерево не
меняют. Меняя пример в одном параграфе, проверь схемы в итогах соседних модулей.

## Команды (slash-команды Claude Code)

### `/book-write §N.N [тема]`
Написать или продолжить параграф. Порядок: конституция → спецификация →
план → файл параграфа → стиль. `status: draft` в frontmatter.

### `/book-analyze §N.N`
Проверить параграф: конституция → спецификация → стиль → консистентность.

### `/book-plan модуль-N`
Спланировать или уточнить модуль; решения зафиксировать в `spec/decisions.md`.

## История правок редактора (повторяющиеся дефекты)

1. **Смешение типов состояния** — примеры регистра сведений (цена, курс) и
   регистра накопления (остатки) в одном параграфе.
2. **Абсолютные формулировки** — всегда смягчать.
3. **Упоминание кода** — запрещено (см. конституцию).
4. **Слабые упражнения «посмотри и ответь»** — без интерпретационного вопроса.
5. **Дублирование параграфов** — жёстко разводить смысл.

## Что не делать

- Не добавляй темы, противоречащие конституции, даже если они «полезны».
- Не меняй `status: ready` без явного запроса автора.
- Не изменяй `metadata.yaml` напрямую — только через `./book.sh`.
- Не генерируй длинные тексты без запроса — сначала предложи план.
