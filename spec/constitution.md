# Конституция книги

> Контракт с читателем и ограничитель для автора.
> Claude Code читает этот файл перед каждым действием.
> Изменения — только через запись в `spec/decisions.md` и `CHANGELOG.md`.

---

## Что эта книга ЕСТЬ

- Учебник **чтения** дерева метаданных: читатель открывает любую конфигурацию и
  называет каждый встреченный тип объекта.
- Перевод дерева обратно на деловой язык: конфигурация читается вслух как
  описание бизнес-процесса, а не как список галочек.
- Практикум в Конфигураторе: с §0.3 и до конца книги Конфигуратор открыт, и
  каждый практический параграф добавляет объект в сквозную конфигурацию.
- Введение в **замысел** автора конфигурации: почему объект устроен именно так,
  а не только что он делает.
- Мост к следующим уровням — языку запросов, СКД, управляемым формам,
  встроенному языку (§9.3), но без захода на их территорию.

## Что эта книга НЕ ЕСТЬ

- **Не справочник API 1С.** Свойства объектов перечисляются только там, где они
  несут смысл для чтения дерева.
- **Не книга о программировании.** Модули, код, обработчики событий — соседний
  слой, у него отдельные книги (граница проведена в §0.4).
- Не курс по конкретной типовой конфигурации: «Канцтовары» — учебный стенд, а не
  предмет изучения.
- Не курс по администрированию, установке и обновлению платформы.

## Метафора книги

**Дерево метаданных — это язык, на котором описан деловой мир.**

Несущая рамка всего курса, разложенная по уровням:

| Уровень | В естественном языке | В дереве метаданных |
|---|---|---|
| 1 | буквы | типы объектов (справочник, документ…) |
| 2 | слова | конкретные объекты («Товары», «Поступление») |
| 3 | грамматика | правила связей (подчинение, владелец, движения) |
| 4 | предложения | набор объектов, описывающий один бизнес-процесс |
| 5 | текст | вся конфигурация как описание деловой системы |
| 6 | авторский замысел | архитектурные решения создателя конфигурации |
| 7 | чтение вслух | перевод дерева обратно на русский деловой язык |

Части речи закреплены жёстко:

```
Примитивный тип      →  описание           (смысл внутри самого значения)
Ссылочный тип        →  имя собственное    (за именем — целый объект)
Справочник           →  существительное    (кто? что?)
Реквизит             →  прилагательное     (какой?)
Табличная часть      →  составное прилагательное
Документ             →  глагол             (что произошло?)
Документ-регистратор →  глагол, меняющий таблицу
Регистр сведений     →  прилагательное во времени
Регистр накопления   →  «сколько чего стало» (амбарная книга)
Отчёт                →  ответ на вопрос пользователя
```

### Каноничные метафоры (закреплены за объектами)

| Образ | Закреплён за | Использовать где-то ещё |
|---|---|---|
| «Язык», части речи | рамка всего курса | — |
| «Амбарная книга» | только регистр накопления | запрещено |
| «Прилагательное во времени» | только регистр сведений | запрещено |
| «Имя собственное» | только ссылочный тип | запрещено |

**Одна метафора — один объект.** Образы не смешиваются в одном абзаце и не
конкурируют между собой.

## Принципы изложения

1. **Конфликт перед объяснением.** Каждый объект вводится через проблему,
   которую он решает: сначала — что ломается без него, потом — решение.
   Схема «проблема → ошибка → решение», не «объяснение → пример».
2. **Два уровня строгости.** Основной текст — разговорный, как объяснение
   коллеге. Строгое определение — только в выноске `>`. Пример: в тексте —
   «создали справочник, теперь на него могут ссылаться другие объекты»;
   в выноске — «объект метаданных добавляет в систему новый ссылочный тип».
3. **Никаких абсолютов.** Не «не хранится нигде», а «не предназначен для»;
   не «удаляются навсегда», а «как правило, платформа удаляет».
4. **ASCII-схема — навигационная карта**, а не замена живому дереву: читатель
   смотрит одновременно на схему в книге и на Конфигуратор на экране.
5. **Термин — награда, не входной билет.** Порядок: бытовое слово → пример →
   строгий термин («папка (объект метаданных, ветка дерева)»).

## Терминология регистров (строго)

| Слово | Значение в книге |
|---|---|
| **запись** | логическая единица регистра: измерения + ресурсы + период + регистратор |
| **строка** | только визуальное представление в пользовательском режиме |
| **значение** | содержимое конкретного поля |
| **состояние** | деловой смысл (цена, курс, остаток) |

Формула записи регистра (введена в §3.3, повторяется во всех регистровых параграфах):

```
Измерения    → о чём запись (ключ)
Ресурсы      → что известно (значение)
Период       → когда это было верно
Регистратор  → почему это появилось
```

Сравнение объектов по вопросу, на который они отвечают (введено в §3.3):

```
Справочник         → «что это такое?»
Документ           → «что произошло?»
Регистр сведений   → «чему это равно прямо сейчас?»
Регистр накопления → «сколько накопилось?»
```

## Что автор не будет делать никогда

- Не употреблять слова **«код», «модуль», «генерация кода»** — даже в обороте
  «это делается автоматически». Вместо них: «настройки соответствия»,
  «Конструктор движений», «платформа создаёт нужные настройки».
- Не смешивать примеры регистра сведений (цена, курс) и регистра накопления
  (остатки) в одном параграфе.
- Не использовать эмодзи, цветные блоки, кричащую вёрстку.
- Не опираться на интуицию из других языков программирования: читатель их не знает.
- Не оставлять упражнение «посмотри и ответь» без интерпретационного вопроса
  («почему здесь так?» / «что сломается, если изменить?»).

## Аудитория (кратко)

**Читатель:** абсолютный новичок без опыта программирования и без знакомства с 1С.
Хочет научиться читать чужое дерево метаданных и переводить его на деловой язык.

**Читатель НЕ:** действующий разработчик 1С, ищущий справочник по свойствам
объектов; и не человек, который пришёл за кодом.

Полное описание — в `spec/specification.md`.
